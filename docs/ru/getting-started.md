# Быстрый старт

> **Language:** [English](../en/getting-started.md) · [Русский](./getting-started.md)

Пять шагов: установить программу, запустить фоновую службу, при необходимости настроить конфиг пользователя, подключить ИИ-агент, проверить, что всё работает.

Зачем это нужно: [Зачем нужен agentd](./why.md).

## Термины

| Термин | Что это |
|--------|---------|
| **ИИ-агент** | Программа, которая пишет и правит код за вас (Claude Code, Cursor, Codex, Gemini CLI, OpenCode, Kimi Code). В командах это флаг `--provider`. |
| **Хук** | Короткая программа, которую агент запускает в нужный момент — например *перед* командой в оболочке. |
| **Демон** | Один постоянно работающий процесс `agentd` на пользователя. Сюда приходят события хуков; здесь принимаются решения. |
| **Установка хуков** | Запись настроек агента, чтобы он вызывал `agentd`. Сам демон при этом не запускается. |
| **Область `project`** | Настройки в текущем репозитории. |
| **Область `user`** | Настройки в домашнем каталоге агента (например `~/.cursor`). |

## 1. Установить программу

См. [Установка](./installation.md). Краткий путь:

```bash
go install github.com/macrox-pro/agentd@latest
```

## 2. Запустить демон

Один процесс на пользователя. Сокет по умолчанию зависит от системы (его можно сменить флагом `--socket`).

```bash
agentd daemon start
agentd daemon status
```

`--foreground` не отсоединяется от терминала (удобно при отладке). Журнал работы — файл `agentd.log` в [каталоге состояния](./configuration.md#каталог-состояния). С `--foreground` те же строки дублируются в stderr.

Если нет файла `~/.agentd.yaml` (или пути из `--config`), **`daemon start` сам создаёт минимальный конфиг** и продолжает работу ([подробнее](./configuration.md#автосоздание-пользовательского-конфига)). Править файл можно после запуска.

Чтобы agentd стартовал при входе в систему:

```bash
agentd daemon enable
```

См. [Эксплуатация → Автозапуск при входе](./operations.md#автозапуск-при-входе).

## 3. Конфиг пользователя (необязателен при первом запуске)

Путь по умолчанию: `~/.agentd.yaml` (или `--config`). Не создавайте файл вручную, если уже выполнили `daemon start` — содержимое совпадает с:

```yaml
version: 1
policy:
  fail: fail_closed
  # offline по умолчанию fail_open — агенты работают, если демон не запущен
  # offline: fail_closed  # останавливать агентов, если демон недоступен
guards:
  secrets:
    enabled: true
    action: ask
```

| Ключ | Смысл |
|------|--------|
| `fail: fail_closed` | Если проверку нельзя выполнить — считать отказ. |
| `offline: fail_open` | Если демон не запущен — не мешать агенту (значение по умолчанию). |
| `guards.secrets.action: ask` | При совпадении с секретом — спросить вас, а не молча запретить. |

Достаточно сохранить файл: демон подхватит изменения. `agentd daemon reload` заново собирает все слои конфига.

**Журнал сессий** (запись вызовов хуков) включён по умолчанию:

```bash
agentd config get trajectory    # trajectory: on (default)
```

Отключить: `agentd config disable trajectory`.

## 4. Подключить агента (установить хуки)

Что agentd видит на этой машине (только чтение, ничего не записывает):

```bash
agentd doctor
```

План или запись хуков для всех агентов, у которых уже есть каталог настроек ([Агенты → Автообнаружение](./providers.md#автообнаружение)):

```bash
agentd install --all-detected          # показать план, не записывать
agentd install --all-detected --yes    # записать файлы хуков агента
```

В интерактивном терминале: `agentd setup` (полный сценарий) или `agentd install` без флагов (короткий). В среде непрерывной интеграции задайте `AGENTD_NO_TUI=1`.

Один агент, этот репозиторий:

```bash
agentd install --provider=claude-code --scope=project
```

В настройках агента прописывается `agentd agenthooks …` (скрытый синоним `agentd hook …` — [зачем](./cli.md#agenthooks-скрытая)). В документации и при ручной настройке удобнее `hook run` / `hook serve` / `hook notify`.

Пути и ограничения по агентам: [Агенты](./providers.md).

## 5. Проверка

```bash
agentd daemon status --json
```

Ожидается `"running": true`. Также в ответе:

| Поле | Смысл |
|------|--------|
| `generation` | Сколько раз конфиг загружался с момента старта (растёт при перезагрузке). |
| `fingerprint` | Контрольная сумма собранного конфига — меняется, когда меняется политика. |
| `async_queue_depth` | Сколько фоновых задач ждёт очереди (журнал, HTTP и т. д.). |
| `async_dropped_count` | Сколько задач отброшено из‑за переполнения очереди. |

Вызовите инструмент в агенте или отправьте тестовое событие:

```bash
echo '{"session_id":"s","cwd":"/tmp","hook_event_name":"PreToolUse","tool_name":"Bash","tool_use_id":"t1","tool_input":{"command":"echo ok"}}' \
  | agentd hook run --provider=claude-code
```

Безопасное событие «перед инструментом» при настройках по умолчанию обычно даёт «пустой» ответ, который агент понимает как «продолжай» (у Claude — `{}`).
