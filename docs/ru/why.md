# Зачем нужен agentd

> **Language:** [English](../en/why.md) · [Русский](./why.md)

**agentd** — фоновая служба на вашем компьютере. Она стоит между ИИ-агентами для кода и вашими правилами: одна политика для всех агентов, ответ в том формате, который агент ждёт, и побочные действия (журнал, HTTP), которые не задерживают этот ответ.

Форматы хуков и запись настроек агентов — библиотека [agenthooks](https://github.com/speakeasy-api/agenthooks).

| Термин | Смысл |
|--------|--------|
| **Хук** | Обработчик события агента (например: перед запуском инструмента). |
| **ИИ-агент** | Программа вроде Claude Code или Cursor (в командах — флаг `--provider`). |
| **Синхронный путь** | Решает: разрешить, спросить или запретить — и формирует ответ агенту. |
| **Асинхронный путь** | Журнал и уведомления. Не должен задерживать ответ. |

## Какие задачи закрывает

| Боль | Без agentd | С agentd |
|------|------------|----------|
| **Много агентов — много форматов** | Отдельный скрипт, свои таймауты и коды выхода под каждый продукт | Короткие команды `hook run` / `serve` / `notify`; политика живёт в демоне |
| **Холодный старт на каждый вызов** | Тяжёлая логика в новом процессе → задержки и срывы по таймауту | Один долгоживущий процесс; каждый вызов читает снимок конфига из памяти |
| **Охрана и журнал в одном скрипте** | Тот же процесс и блокирует агента, и шлёт уведомления | Синхронный конвейер (спросить / запретить) отдельно от очереди (`log` / `http` / `exec`) |
| **Правила разъезжаются по репозиториям** | Скопированные файлы хуков; трудно «одобрить один раз» или временно запретить | Слои YAML (пользователь + проект + временный слой); одобрения и временные блокировки |
| **Нет картины «жив ли шлюз»** | Неясно, работает ли служба и не переполнена ли очередь | `daemon status --json`: поколение конфига, контрольная сумма, глубина очереди, отброшенные задачи |

## Чем не является (версия 1)

Это не вход в аккаунты агентов, не полный конвейер транскриптов, не загрузчик расширений и не отдельный язык правил. Маршруты задаются YAML. Запуск внешней программы (`exec`) — **только в фоне**. Подробнее: [DESIGN.md §11](../../DESIGN.md#11-non-goals-v1).

## Для кого

Те, у кого ИИ-агенты уже в работе и нужна **одна** точка, где можно:

- **ограничивать** — секреты, оболочка, MCP, пути; спросить или запретить; временные блокировки
- **наблюдать** — писать события в `log` / `http` / `exec`, не задерживая агента
- **видеть, что произошло** — один поток хуков по нескольким агентам и `daemon status`
- **отвечать в родном формате агента** — не копируя диалект каждого продукта в свои скрипты

Типичные сценарии: журнал «что агент пытался сделать», оповещения по хукам, одна политика на Claude + Cursor и остальных.
