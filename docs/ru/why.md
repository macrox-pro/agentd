# Зачем нужен agentd

> **Language:** [English](../en/why.md) · [Русский](./why.md)

**agentd** — демон на уровне пользователя ОС: он стоит между ИИ-агентами для кода (Claude Code, Cursor, Codex и др.) и вашей логикой контроля. Одна политика на все агенты, ответ в формате, который ждёт конкретный провайдер, синхронные решения (разрешить / спросить / запретить) и фоновые побочные действия — без переписывания «диалекта» хуков каждого агента.

Форматы обмена и установка в настройки агентов — через библиотеку [agenthooks](https://github.com/speakeasy-api/agenthooks).

**Краткий словарь:** *хук* — обработчик события агента (например «перед запуском инструмента»); *провайдер* — конкретный продукт-агент; *синхронный путь* влияет на ответ агенту; *асинхронный* — аудит и уведомления, не блокируя ответ.

## Какие боли закрывает

| Боль | Без agentd | С agentd |
|------|------------|----------|
| **Много агентов — много форматов** | Отдельные скрипты, свои таймауты и коды выхода под каждого агента | Тонкие команды `hook run` / `serve` / `notify`; политика живёт в демоне |
| **Холодный старт на каждый вызов инструмента** | Тяжёлая логика поднимается в новом процессе → задержки и срывы по таймауту | Долгоживущий демон; на горячем пути — снимок конфига в памяти (без чтения диска на каждый `Invoke`) |
| **Охрана и аудит в одном процессе** | Один скрипт и блокирует агента, и шлёт webhooks/метрики | Синхронный конвейер (спросить / запретить) отдельно от асинхронной очереди (`log` / `http` / `exec` …) — фон не держит ответ агенту |
| **Политики разъезжаются по репозиториям** | Copy-paste конфигов; трудно «одобрить один раз» или временно заблокировать | Слои YAML (пользователь ⊕ проект ⊕ runtime); одобрения и временные блокировки с записью на диск |
| **Нет операционной картины** | Неясно, жив ли «шлюз» и не переполнена ли очередь | `daemon status --json`: поколение конфига, отпечаток, глубина очереди, число отброшенных задач |

## Чем не является (v1)

Не система входа в аккаунты агентов, не конвейер транскриптов диалогов, не загрузчик Go-плагинов и не отдельный язык правил (DSL) для хуков. Цели маршрутизации задаются декларативным YAML; запуск внешних команд (`exec`) в v1 только в **асинхронном** режиме. Подробнее: [DESIGN.md §11](../../DESIGN.md#11-non-goals-v1).

## Для кого

Инженеры, у которых хуки coding-агентов уже в рабочих процессах и нужна **одна** точка для проверок секретов / shell / MCP / путей, опциональной пересылки событий и ответов в родном формате провайдера.
