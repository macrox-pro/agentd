# Диагностика

> **Language:** [English](../en/troubleshooting.md) · [Русский](./troubleshooting.md)

Типичные сбои и фактическое поведение agentd.

## Демон не запущен

`hook run|notify|serve` пишет в stderr `daemon not running`, затем применяет `policy.offline` из локального конфига (встроенные defaults, затем user, проектный слой по рабочему каталогу и runtime, слой за слоем).

| `policy.offline` | Поведение |
|------------------|-----------|
| `fail_open` (по умолчанию) | Код **0**; sync-хуки кодируют нейтральное решение — агент продолжает |
| `fail_closed` | Код **1** (блокирует, если хук агента при ошибке останавливает работу) |

```bash
agentd daemon start
agentd daemon status --json
agentd daemon enable   # по желанию: автозапуск при входе
```

`--socket` у клиента хука и у демона должен совпадать. Операционные логи демона: `agentd.log` в [каталоге состояния](./configuration.md#каталог-состояния).

**Блокировка при старте:** `daemon start` берёт `agentd.lock` рядом с сокетом (в Windows — в [каталоге состояния](./configuration.md#каталог-состояния)) и только под ней удаляет устаревший сокет или PID после падения предыдущего запуска. Если другой старт уже идёт или блокировку держит живой демон, старт завершится с «already running». Устаревшие файлы снимает только один процесс и только под этой блокировкой.

Автозапуск при входе: `agentd daemon enable`. Если `enable` завершился с ошибкой, но в `daemon status --json` `"autostart":{"enabled":true}`, исправьте конфиг и выполните `daemon start` или перелогиньтесь — повторный `enable` не нужен. См. [Эксплуатация → Автозапуск](./operations.md#автозапуск-при-входе).

## Старт демона не выполняется (невалидный пользовательский конфиг)

`agentd daemon start` проверяет пользовательский конфиг до загрузки. При невалидном YAML или ошибке compile:

```text
agentd: invalid user config /path/to/.agentd.yaml: …
```

Старт прерывается; файл **не** переименовывается и не карантинируется. Диагностика офлайн:

```bash
agentd config validate --config ~/.agentd.yaml
```

Исправьте файл и снова выполните `agentd daemon start`. `config validate` и `config show` не создают отсутствующий пользовательский файл.

## Таймауты

Бюджет синхронного пути ≈ 90 % таймаута агента, при желании ограничен `route.sync_timeout` ([Маршрутизация](./dispatch.md)). CLI `--timeout 0` не задаёт срок; демон берёт значения по виду события (30 с / 5 с).

Превышение бюджета отменяет контекст; дальше действует **`policy.fail`** — разрешить или запретить на стороне демона.

`policy.fail` срабатывает, когда синхронный конвейер возвращает **ошибку** (типичный случай — истёк бюджет). Обычный deny от проверки не перекрывается. У sync-цели `grpc` сбои узла обычно закрываются полем `on_error` раньше, чем применится `policy.fail` ([Маршрутизация](./dispatch.md)).

## OpenCode serve: демон недоступен во время сессии

`hook serve` подключается к демону один раз при запуске. Если позже вызов демона не проходит (демон остановлен, ошибка сокета), внешняя часть хука **запоминает** `policy.offline` до конца NDJSON-сессии: в stderr один раз `daemon not running`, дальше каждый кадр обрабатывается по сохранённому офлайн-режиму. Восстановление: перезапустить демон и процесс `hook serve` (или перезагрузить плагин OpenCode).

## Нераспознанный JSON (демон запущен)

Если демон не может разобрать JSON события, агент получает **нейтральное** решение; записи в журнал сессий для этого вызова не создаются. Код завершения внешней части хука в этом случае **0**. Проверьте JSON и соответствие провайдера; для Codex/Kimi пустой stdout часто нормален ([Пустой ответ Codex / Kimi](#пустой-ответ-codex--kimi)).

## Циклы «спросить снова»

Тот же инструмент снова уходит в Ask — нет подходящего одобрения. Возьмите `approval_fingerprint=` из сообщения Ask и выполните `config record-decision` ([Одобрения](./approvals.md)). Неверный `--session-id` не совпадёт с одобрением области `session`.

## Рост async_dropped_count

Растёт счётчик отброшенных задач → очередь полна (`queue_capacity`). Увеличьте ёмкость/число воркеров или сократите число асинхронных целей на событие; `on_overflow: log` добавит предупреждение в лог, но задача всё равно будет отброшена.

## Именованный канал Windows

Канал по умолчанию привязан к SID пользователя (`\\.\pipe\agentd-<SID>`). Другой пользователь или сеанс → ошибка соединения, похожая на «демон не запущен».

## Пустой ответ Codex / Kimi

Для Codex и Kimi нормальный «пустой» ответ — **пустой stdout** и код 0, а не `{}`. Пустой stdout сам по себе не ошибка.

## Поле policy.offline

`policy.offline` задаёт мягкий или жёсткий отказ при недоступном демоне (см. [Демон не запущен](#демон-не-запущен)). Невалидный локальный YAML трактуется как `fail_closed`.

## Не входит в v1

Нет входа в аккаунты агентов, конвейера транскриптов, загрузки Go-плагинов, отдельного DSL хуков, автоматических ретраев async (шторм повторов) и синхронного `exec` с JSON-решением ([DESIGN.md §11](../../DESIGN.md#11-non-goals-v1)).
