# Глоссарий

> **Language:** [English](../en/glossary.md) · [Русский](./glossary.md)

Краткие определения терминов из руководства. Подробности — на указанных страницах.

Канонические русские названия терминов — в [CONVENTIONS.md § Documentation style](../../CONVENTIONS.md#documentation-style) (таблица RU terminology). Ниже — смысл каждого термина, без дублирования той таблицы.

## Основные понятия

| Термин | Смысл | Подробнее |
|--------|--------|-----------|
| **ИИ-агент** | Программа, которая пишет и правит код за вас (Claude Code, Cursor, Codex, Gemini CLI, OpenCode, Kimi Code). | [Агенты](./providers.md) |
| **Поставщик (`--provider`)** | Идентификатор агента в командах хука и установки (например `claude-code`, `cursor`). | [Агенты](./providers.md) |
| **Хук** | Короткая программа, которую агент запускает в нужный момент — например перед командой в оболочке. | [Зачем нужен agentd](./why.md) |
| **Демон** | Один постоянно работающий процесс `agentd` на пользователя. Сюда приходят события; здесь принимаются решения. | [Быстрый старт](./getting-started.md) |
| **Внешняя часть хука** | Тонкий процесс `agentd hook run` / `notify` / `serve`, который агент запускает на каждое событие: читает формат, один раз вызывает демон, пишет ответ — без своей политики. | [CLI → hook](./cli.md#hook) |

## Пути и политика

| Термин | Смысл | Подробнее |
|--------|--------|-----------|
| **Синхронный путь** | Блокирующий конвейер: разрешить, спросить или запретить — и сформировать ответ, который ждёт агент. | [Зачем нужен agentd](./why.md) · [Маршрутизация](./dispatch.md) |
| **Асинхронный путь** | Побочные действия (журнал, HTTP, exec), которые не задерживают синхронный ответ. | [Зачем нужен agentd](./why.md) · [Маршрутизация](./dispatch.md) |
| **Решение** | Результат синхронного пути: **разрешить**, **спросить** или **запретить**. | [Проверки](./guards.md) |
| **Проверка (guard)** | Декларативное ограничение (секреты, оболочка, MCP, пути): спросить или запретить перед инструментом. | [Проверки](./guards.md) |
| **Маршрутизация (dispatch)** | Куда направляется событие: какие проверки и цели, в каком порядке. | [Маршрутизация](./dispatch.md) |
| **Маршрут** | Одно именованное правило в `dispatch:` — фильтр `match` и списки sync/async целей. | [Маршрутизация](./dispatch.md) |
| **Цель (target)** | Куда уходит событие: `builtin` (проверки), `log`, `http`, `exec`, `grpc`, `file`. | [Маршрутизация](./dispatch.md) |
| **Режим (mode)** | Как совмещаются sync и async: `sync_only`, `async_only`, `parallel`, `after_sync` / `sync_then_async`. | [Маршрутизация](./dispatch.md) |
| **Одобрение** | Запись «разрешить» после ответа на ask — повторно не спрашивает, пока действует срок. | [Одобрения](./approvals.md) |
| **Временная блокировка** | Правило во временном слое: запретить подходящие инструменты до указанного времени. | [Одобрения](./approvals.md) |

## Конфиг и хранение

| Термин | Смысл | Подробнее |
|--------|--------|-----------|
| **Слои конфига** | Четыре источника (снизу вверх): defaults, пользователь (`~/.agentd.yaml`), проект (`.agentd.yaml`), временный слой (`runtime.yaml`). | [Конфигурация](./configuration.md) |
| **Временный слой (`runtime`)** | Запись демона: одобрения и временные блокировки (`runtime.yaml` в каталоге состояния). | [Конфигурация](./configuration.md) |
| **Снимок** | Собранный конфиг в памяти демона на каждый вызов хука — без чтения диска на горячем пути. | [Конфигурация](./configuration.md) |
| **Каталог состояния** | Куда демон пишет временный слой, журнал работы и журнал сессий (не пользовательский конфиг). | [Конфигурация → Каталог состояния](./configuration.md#каталог-состояния) |
| **`fail_open`** | При ошибках или недоступном демоне (с `policy.offline: fail_open`) — не мешать агенту, нейтральный ответ. | [Конфигурация → policy](./configuration.md#policy) |
| **`fail_closed`** | При ошибках — считать отказ, агент блокируется. | [Конфигурация → policy](./configuration.md#policy) |
| **Офлайн-политика** | Поведение внешней части хука, когда демон не запущен (`policy.offline`). | [Диагностика → Демон не запущен](./troubleshooting.md#демон-не-запущен) |

## Журнал сессий (trajectory)

| Термин | Смысл | Подробнее |
|--------|--------|-----------|
| **Журнал сессий** | Хронологический JSONL-лог вызовов хуков и связанных событий (`trajectory`, включён по умолчанию). | [Журнал сессий](./trajectory.md) |
| **Транскрипт** | История диалога на диске у агента; опциональный импорт добавляет события `transcript/*` в журнал. | [Журнал сессий → Импорт](./trajectory.md#импорт) |

## Виды событий (`match: kind:`)

Имена в YAML `match:` и `dispatch_defaults`. В JSON агента могут быть другие строки — agentd приводит их к этим.

| Вид (wire) | Типичное имя у агента | Когда |
|------------|----------------------|--------|
| `tool.pre` | `PreToolUse` (Claude), `preToolUse` (Cursor) и т. д. | Перед инструментом |
| `prompt.submitted` | `PromptSubmitted`, `UserPromptSubmit` и т. д. | Пользователь отправил запрос |
| `agent.stop` | `Stop`, `SessionEnd` и т. д. | Завершение сессии |
| `tool.post` | `PostToolUse` и т. д. | После инструмента |
| `notification` | Codex `notify`, observe-only кадры | Только наблюдение |
| `other` | Прочее | По умолчанию только async |

Значения по умолчанию: [Маршрутизация → Виды событий](./dispatch.md#виды-событий-kind).

## Уровни покрытия (trajectory)

| Уровень | Смысл |
|---------|--------|
| **L0 Live** | Каждый вызов хука → `hook/invoked` + `hook/decided` (обязательно для всех шести агентов). |
| **L1 Correlate** | Стабильные id сессии и инструмента в событиях (качество разное; отдельно в доке не выделяем). |
| **L2 Import** | Транскрипт с диска → события `transcript/*` через `session import`. |
| **L3 Thinking** | Строки рассуждений, если поставщик их сохраняет (зависит от агента). |

Матрица по агентам: [Журнал сессий → Уровни покрытия](./trajectory.md#уровни-покрытия).

## Технические термины

| Термин | Смысл |
|--------|--------|
| **NDJSON** | JSON построчно — один объект на строку (OpenCode `hook serve` на stdin/stdout). |
| **TUI** | Текстовый интерфейс в терминале — мастер `agentd setup`, голый `agentd install`. |
| **IPC** | Обмен между процессами — gRPC через Unix-сокет (Linux/macOS) или именованный канал (Windows). |
| **TTL** | Срок действия — как долго одобрение остаётся в силе. |
| **gRPC** | Протокол RPC между внешней частью хука, CLI управления и демоном. |
